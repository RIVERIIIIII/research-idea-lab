# 生存性机制发现方法

本文件是研究 skills 的共享推导规范；Research Brief 仍是范围约束。不得依据本规范自动放宽 Brief、改变确认状态或将旧 corpus 视为正式结论。

## 两条知识线

- 经典光网络生存性：问题、经典方案、优化依赖的条件、决策变量、风险模型、资源共享条件与适用边界。
- 大模型训练/推理任务：特性及证据、适用条件、可观测性、可预测性、可控制性、获取信息或执行控制的成本。

分别建立知识基础，再交叉分析；不要求每篇论文同时覆盖两条线，也不要求任务特性为大模型独有。相关邻域中的相似机制必须纳入回查。

## 六步因果链

经典问题 → 经典方案 → 传统局限 → 场景特性 → 新决策机制 → 优化收益。

1. 经典问题：明确保障对象、故障模型与目标。
2. 经典方案：说明原方案如何决策、依靠什么条件实现保护、恢复或资源共享。
3. 传统局限：定位限制决策机会的假设或边界；原场景中的合理假设不应被描述为普遍缺陷。
4. 场景特性：引用真实证据与适用条件，区分可观测、可预测和可控制；不能把观察到规律直接等同于可任意调度。
5. 新决策机制：明确特性如何改变信息、约束、风险模型、变量或资源利用条件，以及具体改变哪个决策。重点解释③→④→⑤，不以“联合优化”替代因果解释。
6. 优化收益：解释相对于适用的经典方案及简单替代方案，收益如何产生、何时消失，以及信息、协调、等待、迁移等成本。预期收益与已验证结果分开。

改变约束条件、增加决策变量、扩展资源利用条件是可重叠的分析视角，不是穷尽分类或必须凑齐的配额。信息更新也可能改变决策，不强制每个机制增加变量；是否符合算网耦合条件仍按已确认 Brief 判断。

## 光网络贡献核心（硬性要求）

第二点必须属于光网络研究，光网络机制构成贡献核心，不能仅作为传输背景。总主题不扩大到一般跨域系统研究。仅涉及任务调度、状态恢复或计算优化，而未改变光网络生存性机制的方向不符合要求。

每个候选必须明确记录：

1. 大模型任务提供什么信息、约束或可执行控制能力及其证据/适用条件。
2. 它具体改变光网络保护、恢复、资源共享、风险建模或光资源配置中的哪项决策。
3. 从任务特性到光网络决策变化的因果链，以及相对既有机制的具体差异。
4. 移除该特性或禁止相关控制后，光网络决策应如何改变；任务收益和额外成本另行解释。

上述是待论证的筛选条件，不要求已有文献预先证明新机制，也不将规范同步视为现有候选已通过或未通过。

## 候选质量检查

### 实验基线与已有工作差异分开（用户2026-10-27纠正）

- 实验可选适用的经典生存性方法，不要求必须复现最先进或最近邻机制。不能把“尚未优于强顺序法/最近邻”直接等同于第二点不合格。
- 最近邻核查用于说明借鉴范围与独立建模或求解贡献，可以书面对照；不因此自动增加性能实验要求。
- 经典基线须保留其合理保护/恢复能力，以相同故障、预算和保障比较。新增状态记录、预置副本、计算、配置及求解开销不能免费。
- 纸面可证明的是明确条件下相对指定基线的收益或最优值边界；不能由可行集合包含关系推出实际启发式更快、普遍占优或创新性已经成立。

- 特性真实性：证据、适用条件、信息获取与控制可行性是否明确？
- 机制有效性：具体改变了什么决策或可行解空间？不能仅靠修改参数、权重、故障输入或更换算法区分两章，须说明条件变化为何需要不同决策机制。
- 收益可解释性：收益来源、额外成本、公平比较条件与失效边界是否清楚？不得把多投入资源或降低保障要求的收益归因于新机制。
- 研究新颖性核查：检查同问题、同机制、相邻领域及简单替代方案；当前未找到不表示不存在，最终由人工审查。
- 反事实：移除任务特性或禁止新增控制后，哪些决策会改变？若收益仍相同，应降低对该特性必要性的判断。

场景替换、模块简单叠加、仅替换指标或增加变量不足以证明机制创新。指标可以揭示真实任务损失，但仍需解释决策变化。

## 分阶段职责

- 精读：提取论文能够支持的链条片段；未知项留空并说明，推断单列。
- 综述：建立经典机制表与任务特性表；标注证据不足，不生成候选机制。
- Gap：建立“经典问题 × 任务特性”机会矩阵，解释为何出现值得调查的问题；机制位置只作待推导说明，不提前生成 hypothesis。
- Hypothesis：在基础事实有依据时，把问题转换为具体机制、比较预测、成本边界及反事实判断；不要求已有论文证明拟议的新机制。
- Back-check：回查问题和机制，不仅检索应用标签；结果隔离在 research/backchecks/。

允许因缺失证据返回上游补充；gap 是机制分析形成的待解决问题，不只是覆盖缺口。保持既有稳定 ID、证据类型、职责边界和最终人工审查 Gate。

## 毕业论文筛选分层

以 Research Brief 的 Thesis Requirements 为上游规范：

| 层级 | 使用标准 |
|---|---|
| 硬性要求 | “广域算力光网络生存性研究”硕士论文主题；光网络机制须为贡献核心，任务特性须实质改变光网络生存性决策；第二点实质机制贡献、独立支撑一章且不重复第一点；允许合理增量，不要求独立投稿；不抄袭并核查具体已有机制差异 |
| 排序偏好 | 优先考虑能够共用基础任务、计算、通信和网络模型的方案，允许必要扩展；不得因此排除推理或其他合理方向 |
| 中期交付 | 约一个月后、日期待定；问题、真实特性、拟议机制、两类差异、收益来源及初步模型/基线/指标/可证伪思路；无需此时完成实验或完整算法实现 |
| 最终要求 | 保留与最终主张相匹配的验证、成本与公平比较、稳定 ID、证据追溯、隔离 back-check 和最终人工审查 |

后续候选分析分别记录：①相对第一点的关键条件变化；②第一点不能直接解决的原因；③不同决策机制；④最接近已有工作的覆盖与具体差异；⑤共享模型与必要扩展（仅用于排序）；⑥中期可讲清内容和未完成验证。

第一点边界采用 Brief 中用户确认的摘要，不自动视为原文核验结果或加入 corpus。章节叙事示例不是已成立方向；具体关系保持开放。本次同步不触发任何现有候选的自动重评。

章节叙事参考见 `research/chapter-narrative-reference.md`：只在具体机制差异明确后选择组织维度，不把示例变为候选或预设第一点缺陷；额外第一点限定须原文核验。
