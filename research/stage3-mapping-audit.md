# 两个条件性问题的映射核验

当前 Brief：CONFIRMED。目的为检查前提，不生成 hypothesis、收益预测或创新候选。新增 030 NetKV 为 partial_text；小规模检索见 stage3-mapping-run.json（2 queries、6 records、无 API errors）。仅 NetKV 纳入当前 corpus，其他结果保持独立线索。本轮不是 hypothesis 之后的 targeted back-check，未写入 backchecks。

## 首先修正执行链

DistServe 的原文执行顺序为 prefill 产生首 token、发送中间 KV、目标实例继续 decode。[@doi-9e89a0eecd7e32a9403c8e879ddb33febd74868da96839007c7c86a268fba4c3#E007] 这意味着阶段交接是具体的数据流；“decode 计算受内存带宽限制”不能直接换成“decode 持续受 WAN 带宽限制”。跨节点模型并行会产生其他通信，但当前未据此指定部署。

NetKV 使用包含 KV 传输成本的请求延迟模型，而 DistServe 的上述首 token 位置不同。[@doi-40a6e6a6631c624764ffeb27e308e16447a0fd4ecc7c15565443605c866f7e29#E001] 两者的 TTFT 计时点/输出流程不能默认相同，后续必须明确用户可见的 first token、第二 token 等阶段边界，不把不同定义混成事实冲突。

## 普通 WAN 替代检查

NetKV 已将计算负载、缓存命中、网络传输成本用于 decode 实例选择。[@doi-40a6e6a6631c624764ffeb27e308e16447a0fd4ecc7c15565443605c866f7e29#E001] [@doi-40a6e6a6631c624764ffeb27e308e16447a0fd4ecc7c15565443605c866f7e29#E002] 因而“把 KV 大小和网络带宽加入调度目标”不足以满足本项目的机制要求。网络状态 oracle 也已是现有抽象。[@doi-40a6e6a6631c624764ffeb27e308e16447a0fd4ecc7c15565443605c866f7e29#E003]

光层变量的出现不自动保证不可替代性：若只是把光网络输出压成可用带宽/延迟，再运行同一个调度，研究核心可能仍是通用 WAN 控制。后续需证明任务动作与连续频谱分配、调制或故障态 QoT 的决策存在双向影响，且影响不能被固定输入的容量代价完整替代。此为本项目筛选条件，不是已成立的研究结论。

## 后续最小补证任务

1. 先明确一个真实部署和一条通信链：交接 KV 或在线迁移 KV，不能混用；分别定义数据可访问端点、发送时机与用户可见延迟。
2. 核验其跨地域部署证据与故障下行为；NetKV related work 中的 GORGO 仅为原文线索，未核验前不纳入事实。
3. 检查既有光网络业务迁移/资源编排能否直接解决对应决策。当前搜索结果多为 RSA/碎片整理，未得到服务迁移正文，不以未搜到认定空白。
4. 若仍只能形成一般 WAN 带宽感知调度，就排除该组合，回到其他有证据的交叉项，而非强行生成候选。

### 当前处置

- GAP-001：仍 LOW；尚未形成具体跨光路数据流与用户可见延迟模型，不推进假设。
- GAP-002：迁移场景的研究依据增强，但问题已有更直接的部分解法；仍 LOW。只能核验“光故障与光资源约束是否改变已有迁移/重计算选择”，不能把迁移本身当新机制。
- 优先补 EdgeFlow 全文：核验状态可访问条件、断连/过载具体模型、是否支持故障后源端不可达、网络和重计算代价、以及多节点选择约束。摘要不足以回答这些问题。
- 如全文仍不能支持光层不可替代的剩余问题，应停推这两个组合并返回其他交叉项，不继续扩展宽泛检索凑候选。

## EdgeFlow 正文核验更新

### 已覆盖的机制

EdgeFlow 已联合决定迁移目标和逐层传输/重算分界，考虑异构计算、显存和端点间带宽，最小化最慢迁移时间。[@doi-343e35e7b4b90a450f7a36bcfd0bcd4ee9f5c63bab90dee0ebd378cf14047226#E004] [@doi-343e35e7b4b90a450f7a36bcfd0bcd4ee9f5c63bab90dee0ebd378cf14047226#E005] [@doi-343e35e7b4b90a450f7a36bcfd0bcd4ee9f5c63bab90dee0ebd378cf14047226#E006] 因而“利用算力减少 KV 传输量”“按带宽选择迁移目标”“重叠计算与传输”均是直接已有机制，不得作为当前新增贡献。

### 恢复场景边界

摘要的断连背景不能自动解释为失联后恢复：正文具体处理过载或计划退出，执行需要从源端传输 KV/activations。[@doi-343e35e7b4b90a450f7a36bcfd0bcd4ee9f5c63bab90dee0ebd378cf14047226#E003] 本轮没有验证源端失联时仍能取得这些状态。若光路完全阻断且没有其他可达路径/副本，不能直接启动此迁移；如果只是软故障、降容量或另一条光路仍可达，则仍需另行判断迁移可行性。这些后半句为适用性推断，不是论文实验结论。

### 光层剩余问题：只能作为待核验关系

已读 EdgeFlow 模型输入为 Bk,n，决策为目标与分界，未联合物理路由、频谱或 QoT。[@doi-343e35e7b4b90a450f7a36bcfd0bcd4ee9f5c63bab90dee0ebd378cf14047226#E006] 可进一步核验的关系是：任务选择改变待传输数据量后，是否会改变光路与频谱的可行分配，而不同光层分配又是否改变迁移目标和分界选择。只有存在这种决策反馈，且既有光网络服务迁移不能直接覆盖，才值得构造假设。

不能仅将式中的带宽换成故障后带宽，或在原算法外加一个 RSA 模块，就认定问题成立。也不以 EdgeFlow 未建模光层证明本领域空白。当前两个 GAP 仍 LOW，尚未通过光层不可替代性与已有工作的剩余差异门槛。

### 新增的实现核验事项

activation 取得/保存、目标模型参数就绪、生成是否暂停、实际模型的 KV/activation 张量维度以及共享路径竞争仍未核验。[@doi-343e35e7b4b90a450f7a36bcfd0bcd4ee9f5c63bab90dee0ebd378cf14047226#E008] 不把 activation 数据量减半视为所有模型通用收益，也不把论文静态迁移完成时间等同于用户可见 token 停顿。

下一步比较光网络现有服务迁移/频谱编排，集中检查上述反馈是否已有表达；如无法建立与普通 WAN 调度不同的决策，排除该组合，回到其他机制交叉项。
