# X02资格审查用：最小场景、联合模型与求解草案

2026-10-26。用途是判断第二研究点是否值得确立，不是正式中期报告或已完成算法。遵循当前Brief的光网络贡献要求，允许硕士层面的合理增量；不以独立投稿为标准。

## 1. 主场景固定

一个自回归推理请求跨站执行连续Transformer模型段。协调端U保留各模型段已经接收的历史输入，A保存受影响模型段K的权重和会话KV。B是预先部署了兼容K的候选接替节点，但没有该请求的最新KV。源A、U、B以及控制面均存活且可达，受损的是数据承载连接，不研究A的存储丢失。

主故障选**单光纤链路中断**；已有保护/转发先按真实能力计入。光路径可能绕行、缺少连续频谱，或恢复后的逐token往返过长。恢复仍可能留在A，不能预先规定迁移。单光纤故障是对前一轮工作场景的固定，不无声替换HYP-001历史软故障statement；软故障留作后续可选情形。

故障后暂停受影响请求，保留其他请求的资源和保障。协调端与相关节点对齐到已确认输入位置N，回滚/裁掉多余的未提交KV，保存采样/位置/模型版本等元信息；处理在途输出和重试去重。快照协调、控制信令、暂停及导入成本均计入恢复，不能因模型写“暂停”便当作零耗时。

### 三类主动作

1. **留在A**：允许原端点重路由、设备支持的频谱/调制调整及电子/IP转发。所有路径按同一资源图检查。
2. **完整KV接替**：从A向B发送K在全部N位置上的KV，配置后续U↔B连接。
3. **部分重建接替**：向B发送U保留的前k个位置输入记录，在B执行模型段前缀重放；同时从A复制后N−k位置的KV。两部分完成并对齐后接替。k=0/ N分别退化为全KV/全重建。

部分重建**借鉴已有计算/传输取舍，不宣称新发明KV恢复方法**。这里是Petals记录重放与ctHO式前缀分割的有条件组合，不是EdgeFlow逐层activation的直接实现。若A已经实际保留了EdgeFlow所需逐层输入，可以将其作为另一种状态配置；未取得这些输入时，不给它虚构一次快速投影重建。主模型不强制依赖全历史逐层activation缓存。

**正确性的条件推导**：在相同因果模型、权重、精度约定、位置和确定性执行下，重放前缀可按位置/层依赖恢复其KV；后缀KV直接复制自同一快照，覆盖互不重叠且合为[0,N)。随后只需重做尚未提交的下一步。它说明数学上的状态自洽，不证明具体推理引擎已经支持这种导入，更不保证不同精度/量化内核逐位相同。必须做小型正确性检查；失败则不能保留混合动作。

### 删去与保留的边界

- 已有最新状态备份若存在，必须允许直接接替；若不存在，不凭空加入。只预置模型权重不等于预置会话状态。
- 不做故障预测、预复制策略设计、源失联、模型重新切分和训练式DP调整。
- 历史记录存储与维护是共同部署成本，所有比较方案使用同一记录策略和资源预算；给无记录基线补同等资源也须公平。
- 若最快可执行光动作也超出允许停顿，模型如实不可行；不能假定所有广域光路均可毫秒建立。

## 2. 连续业务目标与变量

对同一次故障受影响的请求集合I，已知快照、输入长度N_i、可访问记录、候选目标及背景资源。剩余输出长度不作为已知量。

变量是：留存/接替动作a_i，目标b_i，前缀重建长度k_i；状态路径p_H:U→b_i、p_V:A_i→b_i和持续服务路径p_S:U↔b_i；每个透明段的起始频槽f、有效槽数w、调制m，以及配置/传输/重建的开始时刻和必要计算预留。零数据的路径不配置。允许复用已有电路，但相同资源不重复计数。

以检测后的统一决策时刻t0为零。用户最后有效输出为t_last,i，允许故障跨越间隔G_i，则剩余预算H_i=G_i−(t0−t_last,i)。已经逾期的请求不能通过重新起表变成达标。

状态数据量：D_H,i(k)为前缀历史输入记录；D_V,i(k)为后缀KV；C_i,b(k,q)为在预留算力q上重放前缀的成本。按实际KV头数、精度、模型段和布局计算，不套用“activation必减半”。包括B的队列与算力争用，不只用峰值FLOPS。

一种明确的保守协议是：各支路先完成光配置和记录准备，再传输；前缀记录到齐后才重放。两条支路之间允许并行，不在本版另做逐层流水优化。令：

\[
v_H=S_H+P_H+\Pi_H+D_H(k)/b_H+C_{i,b}(k,q),\quad
v_V=S_V+P_V+\Pi_V+D_V(k)/b_V.
\]

其中\Pi为状态数据路径的传播/协议代价，不得漏掉广域传输的传播。仅对非零支路使用相应式。服务连接就绪时间为s_S；导入/验证I_i、切换Q_i、下一token完整执行与交付g_i另计，则

\[
R_i=d_i+\max\{s_S,v_H,v_V\}+I_i+Q_i+g_i.
\]

d_i包含本轮决策耗时；时刻若需等其他请求释放资源，包含实际等待。留在A无状态导入时改用该动作真实关键路径，不能硬加接替成本。恢复后逐token时延\ell_i需满足同一业务约定，不能只抢出首个token。瞬态与稳态的计时都包括传输和传播。

目标为**先最小化受影响请求的最大恢复停顿T，再在同T下减少增量光资源占用**。约束R_i≤T且R_i≤H_i，并满足恢复后服务阈值；无解时明确不满足保障，不默认丢弃较难请求。需讨论尽力恢复时另列接受率，不混入保证模型。

## 3. 必须落实的约束

| 类别 | 数学/操作约束 |
|---|---|
| 状态正确性 | k_i为合法位置边界；重建前缀和复制后缀不重不漏；同一快照、模型、位置与兼容精度；不存在的记录使相应动作不可用 |
| 目标资源 | 兼容权重已部署或计入部署时间；KV、输入缓冲、重建工作区与导入双缓冲的峰值不超过可用显存；U记录存储、A保留旧KV及发送缓冲均计入 |
| 路由 | 所有路径在故障后图上合法；设备不支持的波长转换或OEO不能使用；设备支持时不能为制造收益将其禁用 |
| 频谱 | 起始槽和槽数为整数，透明段沿路相同连续槽块；保护带占用资源；每条有向边/槽/时间片至多一个独占电路 |
| 带宽与共享 | b≤设备/调制/槽数及沿路有效容量；复用同一电路的同时流量之和不能超过容量；不能让状态传输和持续业务各自拿满同一份容量 |
| 光可达性 | 候选(p,m)满足距离/预核验裕度。首版用距离可达性与保守裕度表近似QoT，明确不是完整GN/多信道干扰模型；最终组合重新检查 |
| 服务 | R_i≤H_i；接替后的完整推理链（含其他段）满足时延/速率约定。共享背景业务的最低保障不可被挤掉 |

## 4. 可求解的有限计划模型

先将每个完整可执行方案p编译成请求i的候选计划集P_i：包含上述动作、路径/调制/频谱、时间安排及算力。记录恢复时间r_ip、后续服务约束、各资源时间占用a_ip,jt、显存m_ip,nt、算力u_ip,nt及增量光成本c_ip。把非法或已超过保障的计划剔除。

用z_ip∈{0,1}选择完整计划：

\[
\min_{z,T}\operatorname{lex}\left(T,\sum_{i,p}c_{ip}z_{ip}\right),\quad
\sum_{p\in P_i}z_{ip}=1,\quad
\sum_pr_{ip}z_{ip}\leq\min(T,H_i).
\]

对每个频槽/电路/端口/时间资源jt：\(\sum_{i,p}a_{ip,jt}z_{ip}\leq A_{jt}\)；对每个站点nt另有\(\sum m_{ip,nt}z_{ip}\leq M_{nt}\)、\(\sum u_{ip,nt}z_{ip}\leq F_{nt}\)。路由、频谱连续与状态协议在计划生成时保证；组合后的资源冲突在主问题检查。时间片向上保守取整，误差随网格做敏感性检查。

这是**指定候选路径/恢复策略与时间网格内**的0-1参考模型，不宣称连续时间原问题全局最优。参考模型可以用通用MILP求解；通用求解器本身不构成本课题贡献。

## 5. 拟研究求解方法，而非机械串接

输入是故障快照、每请求状态数据/重建成本、停顿预算、候选节点与光资源；输出是留存或接替、k、光配置、执行时序，或明确不可行。

1. 完整保留原端点/转发方案；检查状态可访问、正确性和模型兼容。
2. 对每个(k,b)推导期限内各状态支路的最低容量，再换算为满足光可达性的最小连续槽块。例：令h=H_i−d_i−I_i−Q_i−g_i，前缀支路需要
   \(b_H\geq D_H(k)/(h-S_H-P_H-\Pi_H-C(k,q))\)，后缀支路需要
   \(b_V\geq D_V(k)/(h-S_V-P_V-\Pi_V)\)。正数据支路分母不正直接不可行。该条件对当前串行支路模型成立，不能套到未经验证的流水协议。
3. 联合生成状态和服务连接；共享光段按容量/时序一起检查。只用总空闲带宽不足以跳过连续槽块和可达性。
4. 按完整资源占用向量做支配裁剪：只有另一方案恢复不慢且逐项资源不多，才能删除；不能仅因路径更长删除可能避开竞争的方案。
5. 小实例完整枚举/MILP；较大实例研究有限宽度联合搜索：按紧迫度和候选数扩展，每层保留B_w个可行的部分计划，必要时有限回退。它可反复改变k与光配置，不是先固定光路后一次调用状态恢复算法。

设保留计划最多P、检查一计划资源成本为A、请求数n，联合搜索主循环约O(n B_w P A)，另计候选生成；完整组合上界P^n。限制路径数K、k的块粒度和搜索宽度控制规模，但可能漏解，应报告对参考解的差距、无解误判和运行耗时，不预设近似保证。

**拟独立研究内容**是故障后状态续接的双支路、瞬态/持续光资源联合模型，以及面向时限的容量界和资源冲突驱动求解。每个单独的恢复、RSA、裁剪或搜索工具均已有，不宣称全新；是否形成足够增量仍需与直接最近邻及导师讨论。若强顺序法已同样有效，算法收益要据实收缩；不能只凭“联合”命名成立。
